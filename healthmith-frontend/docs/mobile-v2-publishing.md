# Mobile V2 퍼블리싱

사용자가 제공한 [Mobile V2 시안](https://www.figma.com/design/Gjob6Huwx466NIfNg5DFnC/healthmith-design?node-id=14-621)과 첨부 이미지를 기준으로 구현했다. Figma 연결 도구의 호출 한도로 직접 조회가 제한되어, 이전 디자인 작업의 화면 SVG·보석 SVG 원본과 생성 스크립트를 함께 확인했다. 화면 전체를 이미지로 붙이지 않고 React 컴포넌트와 CSS로 구성했으며 보석 12종은 원본 SVG를 사용했다.

정식 요구사항은 [DESIGN](https://github.com/TungTungBall/tungtungball/blob/main/docs/DESIGN.md)과 [MVP 범위](https://github.com/TungTungBall/tungtungball/blob/main/docs/decisions/mvp-scope.md)를 따른다. 이 문서는 퍼블리싱 구현과 실행 확인 기록이며 기능 인수 승인이나 새 요구사항이 아니다.

## 화면 확인

`healthmith-frontend/`에서 `pnpm dev`를 실행한다. 헤더 메뉴의 **화면 둘러보기**(`/design`)에서 모든 시안과 기록 상태로 이동할 수 있다.

| 시안 | 경로 | 구현 |
| --- | --- | --- |
| M01 | `/` | 홈·첫 여정·하단 메뉴 |
| M02 | `/preparation/body` | 제약 부위·운동 우선순위·부위 충돌 안내 |
| M03 | `/preparation/goals` | 목적·자유 입력·강도 1~10 |
| M04 | `/routine` | 예시 5단계 루틴·확인 체크 후 준비 화면 이동 |
| M05 | `/camera` | 전신 안내·사용자 클릭 후 기기 카메라 미리보기 |
| M06 | `/workout` | 단계별 보석·횟수·미리보기 증가 버튼 |
| M07 | `/workout/paused` | 횟수 유지·재개·운동 포기 |
| M08 | `/workout/complete` | 보석 완성·예시 결과 |
| M09 | `/feedback` | 근육통 부위·난이도·재미 입력 |
| M10 | `/records` | 예시 기록·요약·차트 |
| M11 | `/camera/permission` | 카메라 권한 거절·미지원 안내 |
| M12 | `/recovery` | 생성 실패 예시·통증 안내·재시도 동선 |
| 로그인 | `/login` | Google 로그인 화면·미리보기 상태 안내 |
| 보석 | `/gems` | 진행 단계 6종·보석 상태 6종 필터와 상세 선택 |

기록의 추가 상태는 `/records?state=empty`, `?state=loading`, `?state=error`에서 확인한다. 기존 `/backend-connection` 화면은 유지하며 헤더 메뉴에서 접근한다.

## 구현 범위

- 바이올렛·에메랄드 색상, 밝은 배경, 아치와 보석 모티프를 적용했다. 화면 폭은 최대 430px이며 320px부터 확인했다. 키보드 포커스, 버튼 선택 상태, 안전 영역, 동작 줄이기 설정을 반영했다.
- `PreviewProvider`가 화면 이동 중 입력·운동·설문 상태를 보관한다. 새로고침하면 초기화되며 서버·브라우저 저장소에 저장하지 않는다.
- 루틴·기록·완료 지표는 예시다. 루틴 확정은 확인 체크 후에만 가능하며 실제 루틴 생성 API는 호출하지 않는다.
- 운동 횟수는 `+1회 미리보기` 버튼으로 바뀐다. 일시정지 시 횟수를 유지하며 뒤로가기로 운동 화면을 열어도 증가 버튼을 제공하지 않는다. 포기 후에는 재개와 설문 진입을 막는다.
- 카메라는 명시적인 허용 버튼을 누를 때만 요청한다. 준비 화면을 나가면 트랙을 종료하고, 권한 확인 중 화면을 나간 경우 뒤늦게 받은 트랙도 종료한다. 영상 업로드·MediaPipe 인식·자동 횟수 측정은 연결하지 않았다.
- 보석 결함 시안은 시각 비교용이다. 실패·능력치 규칙이나 PvP/PvE 기능을 추가한 것은 아니다.

## 2026-11-03 실행 확인

이 Mac에서 Node.js 24.22.1, pnpm 11.25.0, 저장소의 기존 의존성으로 실행했다. 프로젝트의 Node 고정값은 24.20.0이며 이번 실행 버전과 구분한다. 의존성 선언·잠금 파일·공유 설정은 변경하지 않았다.

| 검사 | 실제 결과 |
| --- | --- |
| `pnpm lint` | 통과 |
| `pnpm typecheck` | 통과 |
| `pnpm test:unit` | 2개 통과 |
| `pnpm build` | 프로덕션 빌드 통과 |
| `pnpm test:e2e` | Chromium 데스크톱·Pixel 7 에뮬레이션 총 10개 통과 |
| 프로덕션 화면 캡처 | 390px에서 12개 화면과 보석 갤러리, 320px에서 사전조사 화면 확인 |

E2E는 홈 표시, 입력 거절·초안 확인 동선, 일시정지·재개·포기, 보석 필터와 SVG 로딩, 모든 화면의 응답·가로 넘침·런타임 오류를 검사한다. 캡처와 자동 보고서는 Git 제외 경로에 생성한다.

실제 휴대폰·Safari·카메라 하드웨어·자세 인식 정확도·API 저장·LLM 생성 품질 검사는 이번 결과에 포함하지 않는다. GitHub CI는 해당 커밋의 원격 실행 결과로 별도 확인한다.

## Google 로그인 화면 추가

사용자의 추가 요청과 **로그인 화면과 상태만 퍼블리싱** 범위 확인에 따라 같은 작업 브랜치에 추가했다. 홈의 로그인 링크, 헤더 메뉴, `/design`에서 접근한다.

| 경로 | 표시 상태 |
| --- | --- |
| `/login` | 기본 화면 |
| `/login?state=loading` | 연결 중 예시·버튼 비활성·취소 동작 |
| `/login?state=cancelled` | 취소 안내·다시 시도 |
| `/login?state=error` | 연결 실패 안내·다시 시도 |
| `/login?state=expired` | 세션 만료 안내·다시 시도 |
| `/login?state=unavailable` | 로그인 기능 준비 중 안내 |

Google 버튼을 누르면 연결 준비 중임을 안내하며 외부 인증 요청이나 이동을 실행하지 않는다. 연결 중 예시에서 취소하면 취소 안내로 바뀐다. URL의 허용 목록 밖 상태·중복 상태 값은 기본 화면으로 처리한다. 실제 로그인 완료·계정 생성·세션 저장으로 표시하거나 처리하지 않는다. OAuth 설정·콜백·토큰·로그아웃·접근 제어는 구현 전이며 의존성·환경변수는 추가하지 않았다.

로고는 [Google 공식 G 이미지](https://developers.google.com/static/identity/images/g-logo.png)를 원본으로 보관했고 [로그인 버튼 가이드](https://developers.google.com/identity/branding-guidelines)의 밝은 버튼 색상·문구·로고 비율을 참고했다. 페이지 나머지 영역에는 기존 보석 SVG와 바이올렛 색상을 재사용했다.

같은 Mac의 프로덕션 서버에서 320·390·1440px의 6개 상태를 브라우저로 확인했다. 가로 넘침·이미지 로딩·런타임 오류, 취소→재시도·키보드 실행·홈/메뉴/상태 링크를 검사했다. 버튼 실행 후 외부 인증 요청·쿠키·브라우저 저장소의 세션 생성이 없음을 확인했다. 이는 화면 동작 검사이며 실제 Google 로그인 성공 검사는 아니다.
