# 통증 응답을 반영한 커리큘럼

실제 저장·생성 경로인 `/survey/legacy`에서 선택한 `answers.pain_body_parts`를 서버에서 적용한다. `/survey`의 새 상세 설문은 기존과 같이 저장 미연결 상태이며, 실제 양식으로 가는 안내를 표시한다.

통증 위치는 진단이 아니다. 운동 불가 부위(`physical_limitations.body_parts`)는 기존처럼 후보에서 제외한다. 통증 위치는 별도 선택 항목이며, 우선 운동 부위와 겹쳐도 허용한다. 필드가 없는 과거 제출과 빈 배열은 통증 조절을 추가하지 않는다. 저장·조회·수정 모두 같은 9개 문자열을 사용하며 중복·미등록 위치는 거절한다.

## 서버 적용

`20261123000000_add_pain_aware_curriculum.sql` 마이그레이션이 9개 근거 규칙(`private.pain_adjustment_rules`)과 MVP 3종의 동작 프로필(`private.exercise_motion_profiles`)을 설치한다. 스쿼트·런지는 굽힘·체중 지지, 푸시업은 상지 지지 등의 동작 부하를 연결했다. 이 연결과 수치 조절은 자료의 문구 자체가 아닌 제품 구현 판단이다. 새로운 운동은 이름으로 추측하지 않고 동작 프로필을 등록한다. 통증 응답이 있는 경우 미등록 운동은 후보에서 제외한다. 모든 후보가 없어지면 기존 `NO_ELIGIBLE_EXERCISE`로 반환하고 설문을 생성에 선점하지 않는다.

관련 동작은 **기존 승인된 횟수 범위의 최솟값을 상한으로 사용**한다. 예를 들어 무릎 앞쪽 통증이면 스쿼트는 MVP 기준 5~20회에서 5회, 런지는 4~16회에서 4회로 제한한다. 무릎과 관계없는 푸시업의 횟수 범위는 유지한다. 여러 통증 위치가 같은 운동에 걸려도 중복 감산하지 않는다. 이는 보수적으로 시작하기 위한 제품 규칙이며, 출처가 정한 의학적 횟수나 개인별 안전 보장이 아니다.

추가 중량 없이 편안한 범위로 작게 움직이고 통증이 늘면 멈추도록 안내한다. 출처의 질환별 상세 지침은 서버에 보관하고, 진단되지 않은 사용자에게 그대로 재활 처방하지 않는다. 카메라의 반복 인식 각도는 변경하지 않으므로, 작은 가동 범위의 반복이 모두 인식된다고 보장하지 않는다.

최초 생성·재생성·피드백 후 다음 생성에서 동일한 함수를 사용한다. 후보·변경된 안내·횟수 제한을 작업별로 고정 저장하고, DB의 기존 게시 검증이 AI의 상한 초과나 안내 누락을 거절한다. 쉬웠다는 피드백도 상한을 해제하지 못한다. 원래 설문의 통증 부위는 유지되며 해제·회복 판단을 자동으로 하지 않는다. 운동 후 피드백의 기존 상체·하체·허리 제외 정책도 유지한다.

외부 AI에는 통증 응답·진단·출처 URL 대신 조절한 후보 안내와 횟수 범위만 전달한다. 기존 요약 입력의 건강 정보 제외도 유지한다. 이미 대기 중인 작업의 스냅샷은 바꾸지 않으며 마이그레이션 이후 요청부터 적용한다.

## 검증

- 프런트: 기존·신규 응답 파싱, 9개 위치 전송, 중복·미등록 위치 거절, 응답 비교, 통증·우선 부위 중복 허용.
- 브라우저: 실제 기존 양식의 9개 선택지 선택·해제, 입력 유지, 모바일 가로 넘침 확인.
- 실제 PostgreSQL 통합: 9개 동작 매핑, 저장·조회·수정, 통증 없음·무관한 운동 유지, 미분류 후보 거절과 롤백, 최초·재생성·다음 생성의 횟수 제한, 상한 초과·안내 제거 시 게시 거절.

배포 시 기존 마이그레이션 뒤에 새 SQL을 적용한 후 백엔드와 프런트를 배포한다. MVP seed를 다시 실행해도 개별 작업의 통증 제한은 새 생성 요청에서 계산되며 원본 기본 횟수는 변경하지 않는다.
