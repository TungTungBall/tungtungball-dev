# 사전조사와 운동 후 설문 서버 연결 요청

## 2026-11-23 진행 상황

사전조사 저장·조회·수정을 v2 API로 구현하고 `/survey`의 저장 버튼을 연결했다. 기존 v1과 새 데이터를 분리하며, 새 조건의 루틴 생성·운동 후 설문 저장·카탈로그 확장은 아직 남아 있다. 적용할 DB 변경과 정확한 요청·응답은 [상세 사전조사 구현 계약](../../healthmith-backend/docs/survey-v2.md)을 따른다. 아래 내용은 11월 17일 당시 요청 기록이며 저장 비활성화 설명은 당시 상태다.

## 2026-11-17 요청 기록

2026-11-17. 사용자가 요청한 범위는 프론트 구현과 서버 변경 사항 정리까지다. 서버 코드·SQL·운영 DB는 수정하지 않았다. 아래 새 필드 이름은 협의할 제안이며, 현재 API가 지원하는 계약이 아니다.

## 현재 동작

- `/survey`: 목표 → 경험 → 현재 수준 → 일정 → 제한 부위 → 선택 선호도 → 입력 확인. 필수 입력을 검사하고 이전 단계의 값을 유지한다. 새 저장 버튼은 비활성화되어 있다.
- `/survey/legacy`: 기존 저장·조회·수정·생성 요청 흐름을 유지한다. 새 입력을 이 양식으로 변환하거나 옮기지 않는다.
- `/feedback?sessionId=…`: 강도·시간·만족도·자유 의견을 모두 선택 입력으로 제공한다. 새 설문은 저장하지 않는다. 건너뛰기는 기록 화면 이동이며 서버에 설문 완료를 기록하지 않는다.
- 같은 주소의 `&legacy=1`: 기존 `soreness_body_parts`, `difficulty`, `enjoyment` 저장 경로다. 새 네 항목을 기존 세 항목으로 변환하지 않는다.
- `/feedback`는 세션 없는 새 입력 화면이다. 저장은 비활성화되어 있고 기존 설문 링크는 제공하지 않는다. `/feedback?preview=1`은 이전 디자인 예시를 유지한다.
- `/camera?curriculumId=…`: 실제 확정 루틴을 불러와 단계별 운동명·목표 횟수·동작 안내를 표시한다. 운동 안내 → 실제 카메라 미리보기 → 사용자가 시작 버튼을 누름 → 기존 세션 시작 API 순서다. 카메라 권한 요청만으로 세션을 만들지 않는다.

새 조사·설문 값은 React 화면 상태에만 있다. localStorage, 쿠키, 로그, API, LLM에 기록하지 않는다. 화면 이동·새로고침으로 없어지므로 첫 입력 화면과 확인 화면에 이를 알린다. 저장 연결 전까지 운영 기능 완료로 취급하지 않는다.

## 사전조사

화면 모델은 `src/lib/healthmith/intake.ts`에 있다. 현재 `src/app/survey/types.ts`와 서버 DTO·DB 제약은 기존 3개 부위를 사용하므로 이 모델을 그대로 보내면 안 된다.

| 새 입력 | 필수 여부와 현재 UI 값 | 서버에서 필요한 처리 |
| --- | --- | --- |
| 목표 | 필수: 체력 기르기 / 근력 키우기 / 체중 관리 / 운동 습관 | 안정적인 코드값과 기존 목적 유형의 호환 정책 결정 |
| 경험 | 필수: 처음 시작 / 가끔 경험 / 꾸준히 운동 | `experience` 저장·반환 |
| 현재 수준 | 필수: 기초 동작 / 가벼운 루틴 / 여러 세트 | 경험과 별개의 `current_level` 저장·반환 |
| 일정 | 필수: 10·20·30·45·60분, 주 1~7회 | `available_minutes`, `days_per_week` 검사·저장·반환 |
| 제한 유무 | 필수: 없음 또는 제한 부위 선택 | 미입력과 제약 없음을 구분 |
| 제한 부위 | 목·어깨·팔꿈치·손목·허리·고관절·무릎·발목 | `limitations[]`의 부위·위치·정도를 각각 보존. 기타 없음 |
| 위치 | 선택한 부위마다 필수. 목·허리는 중앙, 나머지는 왼쪽·오른쪽·양쪽 | 부위별 허용 위치와 임상적 의미 검토 |
| 불편 정도 | 선택한 부위마다 필수: 약함·보통·심함 | 진단 정보나 운동 가능 판정으로 간주하지 않음 |
| 선호 강도 | 선택: 가볍게·보통·강하게 | 미선택을 기본 강도로 바꾸지 않고 null 등 명시적 부재 값으로 저장 |
| 우선 부위 | 선택, 위 8개 부위 | 빈 배열 허용. 제한 부위와 겹쳐도 제한 조건 우선 |

제안: 스키마 버전을 구분하고 새 `answers`를 별도 버전으로 받는다. 현행 v1 요청과 저장된 v1 행의 재조회·수정은 유지해야 한다. 8개 부위를 기존 상체·하체·허리로 자동 압축하거나, 옛 데이터에 경험·좌우·정도의 기본값을 채우지 않는다.

현행 v1은 강도와 우선 부위가 필수이고 제한/우선 부위 교집합을 거절한다. 새 화면은 두 선호를 선택으로 두고 제한 우선 안내를 표시한다. 이 차이는 화면에서 우회 전송하지 않는다. 서버가 새 정책을 구현한 뒤 신규 저장·재조회·수정 응답에 모든 값이 보존되는지 검증해야 한다.

## 운동 후 설문

| 제안 필드 | UI 값 | 필요한 처리 |
| --- | --- | --- |
| `effort` | 가벼움 / 적당함 / 힘듦 또는 미응답 | 기존 difficulty와 별도로 의미 합의 |
| `duration_feedback` | 짧음 / 적당함 / 김 또는 미응답 | 새 필드 저장 |
| `satisfaction` | 1~5 또는 미응답 | 기존 enjoyment와 자동 동일시하지 않음 |
| `comment` | 최대 500자, 선택 | 서버 길이 검사·출력 이스케이프·LLM 전송 전 개인정보 처리 정책 |

부분 응답과 건너뛰기를 지원해야 한다. 전체 미응답은 제출 없이 이동할 수 있어야 한다. 건너뛰기를 저장할지는 별도 결정이며, 현재 프론트는 완료·제출 상태를 만들지 않는다.

세션 소유권·운동 완료 상태·중복 제출·재시도·기존 제출 여부를 서버에서 확인한다. 조회 응답에도 스키마 버전과 네 항목이 필요하다. 신규 응답을 기록과 함께 표시하고, 다음 생성 요청에 사용된 피드백 범위를 재현할 수 있어야 한다. 원문 자유 의견을 그대로 LLM에 넣는 것은 이번 변경에 포함하지 않는다.

## 운동 준비와 카메라

현재 단계 응답에는 `target_repetitions`, `pace_instruction`, `internal_focus_instruction`만 있다. 실제 값으로 표시한다. 세트·휴식 시간이 없으므로 `1세트`, `30초` 같은 예시 값을 쓰지 않고 ‘별도 안내 없음’으로 표시한다.

운동 카탈로그에 세트·휴식 시간·시작 자세·흔한 실수·중단 조건·검토된 시범 자료를 추가하고, 최종 검증된 루틴 응답에 포함해야 한다. 루틴별 값과 운동 공통 안내를 구분한다. 현행 5단계 진행·타이머·횟수 판정 방식은 바꾸지 않았다.

프론트는 푸시업·스쿼트·런지의 정적 자세 안내와 외부 시범 링크를 제공한다. 실제 사용자 영상이나 생성 이미지를 자세 시범으로 넣지 않았다. 알려지지 않은 운동 ID는 서버 동작 안내를 보여 주고 시범·상세 주의사항 준비 중임을 표시한다.

새 입력의 제한 정보는 서버의 운동 후보 필터·결과 검증에 사용해야 한다. 단순히 ‘제한을 우선한다’는 문구만 표시했다고 추천 안전성 검증이 구현된 것은 아니다. 기존 신체 제약 정보의 LLM 전송 금지 경계는 유지하며, 전송 필드 변경에는 별도 검토가 필요하다.

## 연결 작업 순서

1. 새 필드 코드·스키마 버전·선택값·빈값·충돌 정책을 서버 담당자와 확정한다.
2. 서버 검증, DB 제약, 저장·재조회·수정, 기존 행 호환을 구현한다.
3. 인증·완료 상태·소유권·재시도 검사를 유지하면서 새 설문 저장과 기록 조회를 연결한다.
4. 신규 버전 지원을 확인한 뒤에만 비활성화된 프론트 저장 버튼을 실제 요청으로 교체한다. 버전 미지원 서버에서는 입력을 보존하고 지원되지 않음을 알린다.
5. 새 조사 저장 → 재조회 → 제한 기반 추천 검증 → 운동 완료 → 부분 설문 저장 또는 건너뛰기 → 기록 재조회까지 통합 검사한다.
