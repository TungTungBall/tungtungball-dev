# 문서·정리

문서 작성이나 팀 기록 취합을 맡았을 때 적용한다.

- 정식 문서는 [문서 저장소](https://github.com/TungTungBall/tungtungball)에 있다. 실행 저장소에 요구사항 사본·새 백로그를 만들지 않는다. [PRD의 기준](https://github.com/TungTungBall/tungtungball/blob/main/docs/PRD.md#문서를-읽는-순서와-기준)에 따라 원문을 연결한다.
- 인수 조건은 사람이 작성·확인한다. AI는 요청의 근거·미확정·질문을 정리하고 문장·체크 표시를 대신 바꾸지 않는다. 예시·선언·설치·실행·합의의 상태를 구분한다.
- 문서 저장소의 `docs/SETUP-PLAN.md`에는 실행 저장소의 실제 경로·버전·명령을 적는다. 두 저장소를 합치거나 앱이 문서 저장소에 없다는 이유로 프로젝트 전체를 미구성이라고 적지 않는다.
- 같은 표·블록은 담당 1명이 수정한다. README 문서 지도와 초기화 계획 5·6절은 정리 담당, 공통 설치·실행 절은 공유 기반 담당이 맡는다. 다른 역할은 근거를 전달한다.
- AI 확인 기록은 기존 `docs/domain/ai-check-log.md`의 `요구사항 정리 (1주차 2일차~)` 표에 모은다. 실제로 받은 제안·확인한 근거·본인이 말한 판단만 기록한다. 다른 사람의 채택·보류나 팀 전체 합의를 만들지 않는다.
- 개인 일지는 `logs/daily/오늘날짜-본인이름.md`에 네 칸·각 1~3줄로 쓴다. 세 번째 칸은 본인 판단을 근거로 하며 공유 AI 표의 날짜·어디서 값만 연결한다.
- 이 지침과 역할 규칙은 문서·실행 저장소에서 같이 관리한다. 링크는 다른 저장소의 로컬 경로를 가정하지 않는다. 개인 지침·로컬 설정·키·개인 경로는 올리지 않는다.
- PR·최신 커밋 승인·병합은 [팀 작업 규칙](https://github.com/TungTungBall/tungtungball/blob/main/docs/team/working-agreement.md)을 따른다. 개인의 동의를 전원의 검토나 GitHub Approve로 기록하지 않는다.
